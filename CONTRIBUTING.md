# Contribution Guidelines

Please ensure your pull request adheres to the following guidelines:

- Search previous suggestions before making a new one, as yours may be a duplicate.
- Make an individual pull request for each suggestion.
- Add new links in alphabetical order within the relevant category.
- Use the following format: `[Name](link) - One-sentence description. *(Tags: tag, tag, tag.)*`
- Keep descriptions factual, concise, and neutral.
- Check your spelling and grammar.
- Make sure your text editor is set to remove trailing whitespace.
- Give the pull request and commit a useful title.
- Include a link to the repository or product page in the body of your pull request.

## What makes a good submission?

A good submission is:

- Clearly focused on CV or resume creation.
- Useful to a broad set of users or a clearly defined audience.
- Maintained, or at least still usable with current documentation.
- Distinct from existing entries in workflow, audience, output style, or ecosystem.
- Transparent about licensing, pricing, or hosting expectations.

## What is usually rejected?

Submissions are usually rejected if they are:

- Unrelated to CV or resume creation.
- Obvious duplicates or near-duplicates of existing entries without a meaningful difference.
- Bare repositories with little documentation or no clear usage path.
- Broken links, abandoned products, or resources that appear unmaintained.
- Overly promotional descriptions instead of neutral summaries.

## Are commercial tools allowed?

Yes. Commercial or freemium tools are welcome if they are genuinely useful, transparent about their offering, and clearly labeled.

## Should inactive resources be removed?

Yes. Broken links, archived repositories, or resources that are no longer practical for new users may be removed to keep the list trustworthy.

Thank you for your suggestions.
